# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Static D&D world wiki site (Russian language) built with Eleventy (11ty) and deployed to GitHub Pages.

## Development

```bash
npm install
npm run serve    # starts dev server with hot reload
npm run build    # builds to _site/
```

## Architecture

Start from `eleventy.config.js`: it defines all collections (one per content section, sorted with `localeCompare(..., "ru")`), passthrough copies, and the `/dnd.images/` pathPrefix (in `.njk` always pass internal URLs through `| url`; content pages use relative links).

- **Source/output:** `src/` → `_site/` (gitignored)
- **Content sections:** one folder per section under `src/` (Characters, Personalities, Races, Classes, Creatures, Maps). Each has a directory data file `src/<Section>/<Section>.json` (layout, tags, etc.) and an index page using the `list.njk` layout with `collectionTag` front matter
- **Standalone pages:** `src/Glossary/`, `src/Rules/` — self-contained front matter, excluded from collections
- **Layouts:** see `src/_includes/` — `base.njk` is the HTML wrapper (top nav, breadcrumbs, auto-TOC built from h2/h3, initiative tracker shell); section layouts (`character.njk`, `personalities.njk`, `creature.njk`, `race.njk`) chain to it
- **Stat components:** character/personality/creature pages keep ability scores and combat values in front matter (`stats:`, `combat:` — see any `src/Characters/*/index.md` for the format), rendered by `src/_includes/stat-block.njk` and `src/_includes/combat-block.njk` (modifiers are computed in the template; combat notes render as popovers)
- **Battle widgets:** `<battle-toolbar>` and `<add-to-battle>` come from the neighboring dice-roller repo (loaded remotely in `base.njk` from `https://ramil-k.github.io/dice-roller/`). The toolbar is a dock flush in the bottom-right corner (initiative / battle map / dice buttons); the first two open the shared **battle screen** — a full-viewport grid with the map, the token pool row and the embedded initiative tracker stacked on the left and a toolbar column on the right (map tools on top, dock-style area toggles + d20 at the bottom; Escape closes, no close button). The initiative button opens the tracker as a HUD without the map — the page stays visible and clickable through the empty map cell; area toggles persist in localStorage `battle-mat-ui`; the screen survives navigation between site pages within a tab (per-tab flag in sessionStorage `battle-mat-screen`, set on open, cleared by Escape — the toolbar reopens it on the next page in the same shape, other tabs unaffected). Everything shares one encounter document (localStorage `battle-mat-canvas`, cross-tab sync) — combatants, combat stats, grid and viewport all live in that single JSON Canvas doc. Every «В бой» click adds one combatant *instance* to the encounter (later instances of a type get a random Russian adjective from `src/scripts/battle-config.js`, which also imports `add-to-battle.js`); the combatant shows in the tracker at once but starts **unplaced** (`x-battleMat.placed:false`) — it appears in the screen's **Reserve** pool tab and is drawn on the map only when the DM drags/click-places it from Reserve. The sync button in the screen toolbar opens the room panel (`label-sync*` strings): rooms live on the dice-roller-sync server (`https://universal.ramilkarimov.me:9443`, repo `ramil-k/dice-roller-sync`) and let several devices co-edit one encounter over Yjs CRDT; the room name in the panel is an invite link (`<page>#bm-room=<code>` — opening it on any site page joins the room, the hash is stripped after). Room members see each other's cursors on the map and colored focus rings on tracker inputs; the panel has a name field and a color palette (localStorage `battle-mat-profile`), the name falls back to the tg-login profile, and every player's name is prefixed with an adjective from the same Russian list in `battle-config.js` that names duplicate combatants. Attached map images can be resized by handles and locked (`label-image`/`label-lock`/`label-unlock`/`label-imageremove`). Tracker rows have an editable name; UI strings are localized via `label-*` attributes on `<battle-toolbar>` in `base.njk`; dock theming in `shared.css` via `--bt-*` (`--bm-atb-*` for add-to-battle; the battle screen itself uses its own dark `--bm-*` palette). The standalone `<battle-mat>`/`<initiative-tracker>`/`<roll-any-dice>` launchers still exist in the package but the site no longer mounts them
- **Telegram login:** `src/scripts/tg-login.js` — `<tg-login>` web component (identification only, no server, popup answer trusted as is); mounted in the top nav in `base.njk`, hides itself until its `bot-id` attribute is filled in. Profile in localStorage (`dnd-tg-user`); other scripts read it via `currentUser()` or the `tg-auth-change` window event
- **Head crops:** `swift tools/headcrop.swift <portrait> <dir>/head.jpg` — 320×320 square head close-up (Vision: face → body-pose → animal → saliency); every character/personality/creature gets one, the home page and «В бой» use it via the computed `previewImage` (first existing of `preview` / `portrait` / `gallery[0]`)
- **Icons:** `src/icons/` — SVGs from Sergey Chikin's free set (https://sergeychikin.ru/365/, download as `https://sergeychikin.ru/365/<category>/<name>.svg`). Render icons at 40px or larger — never smaller
- **Rogue feats:** the rogue class (`src/Classes/rogue/`) has no subclasses — players pick one feat per level; the class resource is the two-sided scale «Тень ↔ Кураж» (rules in the `#scale` section of the class page). Alchemy (`#poisons`) is Morrowind-style: `src/_data/rogueRecipes.js` holds effects (harm/boon, tier, save, three stack rows), ingredients (region + four effect ids, mixed harm and boon, every effect on at least two ingredients) and основы. A dose holds N ingredients by tier (2/3/4/5/7); an effect lands if at least two ingredients share it, its strength is that count minus one; effects above the brewer's tier are dropped; the same dose is a poison on a blade or a potion when drunk. Shortcodes: `{% effectCards "harm:apprentice" %}`, `{% ingredientCards "region" %}`, `{% baseCards %}` on the class page, `{% ingredientPicks "id:note; ..." %}` on character pages; `{% alchemyLab "known:page; tier:…; int:…; still:…; retort:…" %}` renders a «Сварить дозу» button that opens the brewing calculator in a `<dialog>` (`src/scripts/alchemy-lab.js`, loaded when the page sets `alchemyLab: true`; `known:page` limits the picker to the ids that `ingredientPicks` on the same page stores in `data-known-ingredients`). Entry feat `apothecary-kit` (mechanics, three ingredients, +1 per level, more by exploring regions); `poisoner` strips a boon from a dose and adds +1 DC, `apothecary` strips a harm and adds a dose, both repeatable; `assay` identifies substances. Feats live in `src/_data/rogueFeats.js` (groups incl. «Шпага» — the fencer-in-the-open group; spheres of influence; requirements; optional `side: "shadow"|"panache"` — Тень / Кураж, titles and icons in the `sides` array — rendered as a third card icon and a colored left border); shortcodes in `eleventy.config.js` render them as cards: `{% featCards "group" %}` / `{% featLegend %}` on the class page, `{% featPicks "id:level:note; ..." %}` on personality pages (relative asset/link paths assume depth-two pages)
- **Dice widgets:** `<roll-dice>`/`<roll-any-dice>` custom elements loaded remotely in `base.njk`
- **Styling:** `src/styles/shared.css` — single stylesheet; theme colors/fonts/shadows are CSS variables in `:root`, use them instead of hardcoded values
- **Deployment:** `.github/workflows/deploy.yml` — builds and deploys to GitHub Pages on push to main
