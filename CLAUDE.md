# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Static D&D world wiki site (Russian language) built with Eleventy (11ty) and deployed to GitHub Pages.

## Development

```bash
npm install
npm run serve    # starts dev server with hot reload
npm run build    # builds to _site/
```

## Architecture

Start from `eleventy.config.js`: it defines all collections (one per content section, sorted with `localeCompare(..., "ru")`), passthrough copies, and the `/dnd.images/` pathPrefix (in `.njk` always pass internal URLs through `| url`; content pages use relative links).

- **Source/output:** `src/` → `_site/` (gitignored)
- **Content sections:** one folder per section under `src/` (Characters, Personalities, Races, Classes, Creatures, Maps, Stories). Each has a directory data file `src/<Section>/<Section>.json` (layout, tags, etc.) and an index page using the `list.njk` layout with `collectionTag` front matter. Stories (`src/Stories/<slug>/index.md`, layout `story.njk`) are prose with a `date:` front matter field; the `stories` collection is sorted by date descending, and the `ruDate` filter renders it in Russian («12 сентября 2026»); lists show the date when `withDate: true`
- **Standalone pages:** `src/Glossary/`, `src/Rules/` — self-contained front matter, excluded from collections
- **Layouts:** see `src/_includes/` — `base.njk` is the HTML wrapper (top nav, breadcrumbs, auto-TOC built from h2/h3, initiative tracker shell); section layouts (`character.njk`, `personalities.njk`, `creature.njk`, `race.njk`) chain to it
- **Stat components:** character/personality/creature pages keep ability scores and combat values in front matter (`stats:`, `combat:` — see any `src/Characters/*/index.md` for the format), rendered by `src/_includes/stat-block.njk` and `src/_includes/combat-block.njk` (modifiers are computed in the template; combat notes render as popovers)
- **Battle widgets:** `<battle-toolbar>` and `<add-to-battle>` come from the neighboring dice-roller repo, loaded remotely from `https://ramil-k.github.io/dice-roller/` by `src/scripts/battle-config.js` — the only eager script of the widgets: it imports `battle-toolbar.js` (the dock, every page), sets the Russian instance adjectives via `BattleToolbar.adjectives`, and dynamically imports `add-to-battle.js` only when the page has an `<add-to-battle>` and `roll-dice.js` only when it has `<roll-dice>`/`<roll-any-dice>`/`<roll-log>`. The battle screen, dice overlay and the sync chunk (yjs) load only when activated (dock click, «В бой», invite link) — a configured room does not connect on plain page loads. The toolbar is a dock flush in the bottom-right corner (initiative / battle map / dice buttons); the first two open the shared **battle screen** — a full-viewport grid with the map, the token pool row and the embedded initiative tracker stacked on the left and a toolbar column on the right (map tools on top, dock-style area toggles + d20 at the bottom; Escape closes, no close button). The initiative button opens the tracker as a HUD without the map — the page stays visible and clickable through the empty map cell; area toggles persist in localStorage `battle-mat-ui`; the screen survives navigation between site pages within a tab (per-tab flag in sessionStorage `battle-mat-screen`, set on open, cleared by Escape — the toolbar reopens it on the next page in the same shape, other tabs unaffected). Everything shares one encounter document (localStorage `battle-mat-canvas`, cross-tab sync) — combatants, combat stats, grid and viewport all live in that single JSON Canvas doc. Every «В бой» click adds one combatant *instance* to the encounter (later instances of a type get a random Russian adjective from `src/scripts/battle-config.js`, which also imports `add-to-battle.js`); the combatant shows in the tracker at once but starts **unplaced** (`x-battleMat.placed:false`) — it appears in the screen's **Reserve** pool tab and is drawn on the map only when the DM drags/click-places it from Reserve. The sync button in the screen toolbar opens the room panel (`label-sync*` strings): rooms live on the dice-roller-sync server (`https://universal.ramilkarimov.me:9443`, repo `ramil-k/dice-roller-sync`, local checkout `~/Projects/dice-roller-sync` — `src/server.js` REST + ws gate, `src/wsdoc.js` vendored y-websocket server on yjs 13, `src/persistence.js` one `.yupdate` blob per room, `src/images.js` per-room image store; a push to its main deploys to `/opt/dice-roller-sync` on the host via GH Actions) and let several devices co-edit one encounter over Yjs CRDT; the client half is `~/Projects/dice-roller` (`src/battle-mat/sync.js` bridge plain doc ↔ Y.Doc, `store.js`, `tracker.js`, `overlay.js`; a push to its main rebuilds `dist/` into GitHub Pages, which is what `base.njk` loads — nothing to commit under `dist/`). Attached map images are uploaded to the room's image store (`POST /rooms/<code>/images`) and referenced by URL once a session is connected; outside a room they stay inline as data URIs. `<add-to-battle>` resolves the site-relative `image` to an absolute URL so avatars work for peers on another origin; the room name in the panel is an invite link (`<page>#bm-room=<code>` — opening it on any site page joins the room, the hash is stripped after). Room members see each other's cursors on the map and colored focus rings on tracker inputs; the panel has a name field and a color palette (localStorage `battle-mat-profile`), the name falls back to the tg-login profile, and every player's name is prefixed with an adjective from the same Russian list in `battle-config.js` that names duplicate combatants. Attached map images can be resized by handles and locked (`label-image`/`label-lock`/`label-unlock`/`label-imageremove`). Tracker rows have an editable name; UI strings are localized via `label-*` attributes on `<battle-toolbar>` in `base.njk`; dock theming in `shared.css` via `--bt-*` (`--bm-atb-*` for add-to-battle; the battle screen itself uses its own dark `--bm-*` palette). The standalone `<battle-mat>`/`<initiative-tracker>`/`<roll-any-dice>` launchers still exist in the package but the site no longer mounts them
- **Telegram login:** `src/scripts/tg-login.js` — `<tg-login>` web component (identification only, no server, popup answer trusted as is); mounted in the top nav in `base.njk`, hides itself until its `bot-id` attribute is filled in. Profile in localStorage (`dnd-tg-user`); other scripts read it via `currentUser()` or the `tg-auth-change` window event
- **Head crops:** `swift tools/headcrop.swift <portrait> <dir>/head.jpg` — 320×320 square head close-up (Vision: face → body-pose → animal → saliency); every character/personality/creature gets one, the home page and «В бой» use it via the computed `previewImage` (first existing of `preview` / `portrait` / `gallery[0]`)
- **Icons:** `src/icons/` — SVGs from Sergey Chikin's free set (https://sergeychikin.ru/365/, download as `https://sergeychikin.ru/365/<category>/<name>.svg`). Render icons at 40px or larger — never smaller
- **Feats and alchemy:** feats are a shared system, not a rogue-only one — the whole registry lives in `src/_data/feats.js` and renders on the standalone page `src/Feats/` (`src/Feats/index.html`). A feat's `classes` field sets availability: absent means any class may take it, `["rogue"]` means it belongs to that class. **How a character gets a feat:** the rogue picks one per level; every other class takes one **instead of an ability score improvement** — each class table row that offers «Повышение характеристик» also offers «общая черта» linking to `/Feats/`, and each class page carries a «Черты» paragraph after its level table. Fighting styles of the fighter, ranger and savage are feats too — the `style` group, open to every class — and on the levels those classes grant «Боевой стиль» a character may take any feat instead; the three class pages embed the group with `{% featCards "style", true %}` (cards without ids, names linking to `/Feats/`). `{% featList %}` renders every card plus a three-axis filter toolbar (group / sphere of influence / availability, `src/scripts/feat-filter.js`, loaded when a page sets `featFilter: true`); `{% featList "rogue" %}` on a class page ships with that class chip already pressed, so the page opens filtered but the chip can be unpressed to see everything. Cards on class pages carry no `id` — a feat's canonical anchor is `/Feats/#feat-<id>`, and `{% featPicks "id:level:note; ..." %}` on character/personality pages links there. `legendary-hero` is a narrative feat granted not by the GM but by the artist-Сказитель's «Легенда о герое» (`src/Classes/artist/index.md`, `#hero-legend`), repeatable up to three per hero; the rolled effect (+1d4 КЗ or +1d4 to-hit) goes in the `featPicks` note and, for to-hit, is duplicated as a `Легендарный герой +N` modifier in `weaponPicks` (КЗ goes into `combat.КЗ.note`). Optional `side: "shadow"|"panache"` (Тень / Кураж) is rogue-only flavour: a third card icon and a colored left border. Shortcode asset and link paths go through the `url` filter, so cards render at any page depth. Alchemy (`/Feats/#alchemy`) is Morrowind-style: `src/_data/alchemy.js` holds tiers, effects (harm/boon, save, three stack rows), ingredients (region + four effect ids, mixed harm and boon, every effect on at least two ingredients) and основы. **The alchemist tier is the number of alchemy feats taken** (one feat = one tier, repeats count) — `tiers` maps that to dose capacity (3/4/5/6/7) and the DC bonus (2/3/4/5/6); poison DC is 8 + tier bonus + Int. An effect lands if at least two ingredients share it, its strength is that count minus one; the same dose is a poison on a blade or a potion when drunk. Shortcodes: `{% effectCards "harm" %}`, `{% ingredientCards "region" %}`, `{% baseCards %}` on the Feats page, `{% ingredientPicks "id:note; ..." %}` on character pages; `{% alchemyLab "known:page; tier:…; int:…; still:…; retort:…" %}` renders a «Сварить дозу» button opening the brewing calculator in a `<dialog>` (`src/scripts/alchemy-lab.js`, loaded when the page sets `alchemyLab: true`; capacity and DC bonus come from `tiers` in the payload, not from the script; `known:page` limits the picker to the ids that `ingredientPicks` on the same page stores in `data-known-ingredients`). Alchemy has **two entry feats**: `apothecary-kit` (herbs, poisons and potions — every «Повсюду» herb plus the home region's, +1 per level, more by exploring regions) and `demolition` (gunpowder — grants the thrown bases regardless of tier and knows only powder/naphtha/brimstone); either one makes a character an Ученик, both together a Подмастерье. `poisoner` strips a boon from a dose, `apothecary` strips a harm and adds a dose, both repeatable and both raising the tier; `assay` identifies substances; `heavy-charge` (repeatable) widens thrown radius; `arsonist` (objects and rigging ignite from the first stack of Горение, double fire damage to objects, a longer fire pool that may lie as a strip) and `fuse` (a charge left with a timed or touch-triggered fuse instead of thrown) extend the powder chain, both `req: Подрывник` and both raise the tier; `anatomist` harvests trophies and unlocks the `mutagen` base. **Two ranger subsystems live here now.** Trophies are ingredients in the `trophy` region (harvested from a monster's corpse, keep for a month), and the `mutagen` base makes a dose permanent — boons stay forever, and every harm in the mix stays too as the price, with no save. Brewing and wearing are deliberately different feats: `anatomist` brews (and may hand the mutagen to someone else), while `graft` — the only new feat in the `common` group, and the one feat that does **not** raise the alchemist tier because it teaches no craft — lets a body carry one mutation per taking. `bomb`/`fire`/`smoke` are thrown bases costing 2 slots that hit an area without distinguishing friend from foe; effects `blast`/`burn` use a Ловкость save. `{% mutagenCards %}` renders the trophy list on the ranger page. The ranger's Охотник на чудовищ gets free `graft` at 3 and four more at 15; Арсеналист gets free `demolition` + `heavy-charge` at 11. The rogue class (`src/Classes/rogue/`) has no subclasses — it picks one feat per level and its class resource is the two-sided scale «Тень ↔ Кураж» (`#scale` section). `{% scaleTracker "id:…; name:…; feats:…" %}` puts a «Открыть шкалу» button on a character page that opens the scale tracker in a `<dialog>` (`src/scripts/scale-tracker.js`, loaded when the page sets `scaleTracker: true`) — same launch pattern as `alchemyLab`, and it reuses the lab's dialog/button styles. It tracks the −3..+3 position, enforces that a spend only works from your own side, shows the Тень 2 / Кураж 2 threshold text, and renders the side-tagged feats **in full** (name, req, description) for whichever side the scale currently sits on. Passing `feats:` narrows that to the character's own picks and is validated against the registry at build time; omitting it ships every side-tagged feat, which is how the class page (`src/Classes/rogue/`, `#scale` section) uses it. State lives in `localStorage` under `dnd-scale-<id>` (position + a short log), so each character is independent — always pass a distinct `id:`, since it defaults to the page path
- **Weapons and armor:** the same registry pattern as feats — one markdown file per item in `src/_data/equipment/weapons/NN-id.md` and `src/_data/equipment/armor/NN-id.md` (numeric prefix = order, filename = id, body = description, may be empty), loaded and validated by `src/_data/equipment.js` (it reuses `parseFrontMatter` and `md` exported from `feats.js`). Canonical page is `src/Equipment/index.html` (`/Equipment/`, nav item «Снаряжение»), anchors `/Equipment/#weapon-<id>` and `/Equipment/#armor-<id>`; cards elsewhere carry no `id` and link there. Weapon fields: `group` (sword/dagger/axe/polearm/bow/crossbow/gun/shield/special), `tier` (simple/martial/powder), `damage` («1d8», or «1d6/1d8» for `versatile`), `type` written in Russian (рубящий/колющий/дробящий — the three from Rules; режущий, пробивающий and проникающий were normalized away), `props` list (light, finesse, heavy, two-handed, versatile, thrown, ranged, loading = crossbow one shot per attack, reload = powder action to reload, reach), `range` («20/60», required with thrown/ranged/reach). Armor fields: `slot` (body = whole suit, shield, extra = helmet/gloves/skirt with **no КБ**, «for looks»), `weight` (body only: light = full Dex, medium = Dex capped at +2, heavy = no Dex; the cap lives in `weights` in `equipment.js`), `ac` (body: suit КБ including the 10; shield: bonus). Suits are whole sets, not stacking pieces. Shortcodes: `{% weaponList %}` / `{% armorList %}` (full list + filter toolbar, built by the shared `filterToolbar` helper that `featList` also uses; `src/scripts/feat-filter.js` reads its axes from the chips' `data-axis`, so the page sets `featFilter: true`; each list sits in its own `.equip-list` wrapper because the script scopes to the toolbar's parent), `{% weaponCards "group" %}` / `{% armorCards "slot" %}` slices, and on character/personality pages `{% weaponPicks "id ×N: mods : note; ..." %}` and `{% armorPicks "id: note; id; +1 label; ..." %}`. `weaponPicks` mods are comma-separated: `владение N` (proficiency, per weapon — there is no level-scaled proficiency bonus in these rules), `Имя +N` (extra to-hit with a caption, e.g. Арсеналист +1, Стрельба +2), `Имя +N к урону` (extra damage, e.g. дуэлянт +2 к урону), a bare ability name `Сила`/`Ловкость`/`Харизма` to override the default (warlock uses Харизма). The shortcode reads the page's `stats:` via `pageData(this.ctx, "stats")` (in Liquid `this.ctx` is a Context object, data comes from `ctx.get([key])`) and renders «Меткость `<roll-dice>1d20+N</roll-dice>` · Урон `<roll-dice>1d8+M</roll-dice>`» plus a breakdown line; ability default: finesse → the higher of Сила/Ловкость, ranged or light → Ловкость, else Сила. `armorPicks` allows at most one body and one shield (build error otherwise), entries starting with `+N text` are flat bonuses (боевой стиль Защита, Укреплённый, Первобытная броня), and it prints a «КБ 16 = 12 (…) + 4 (Ловкость)» total line; if the page's `combat.КБ.value` differs from that total the build prints a `console.warn` — `combat.КБ` stays hand-written because «В бой» reads it, and its `note` is kept equal to the formula. Non-weapon bullets (ammunition, grenades) stay as plain markdown after the shortcode. Icons for the axes came from the same Chikin set (`tomahawk`, `halberd`, `bow2`, `crossbow`, `weapon`, `weapon2`, `hookey`, `stick`, `culverin`, `bardiche`, `trident`, `mace`, `plate-armour2`, `helmet`, `leather-jacket`, `crusades1`), all black like the rest — the set's colored icons (sword, bomb) were skipped on purpose
- **Dice widgets:** `<roll-dice>`/`<roll-any-dice>` custom elements from dice-roller; `battle-config.js` loads `roll-dice.js` only on pages that contain them
- **Styling:** `src/styles/shared.css` — single stylesheet; theme colors/fonts/shadows are CSS variables in `:root`, use them instead of hardcoded values
- **Deployment:** `.github/workflows/deploy.yml` — builds and deploys to GitHub Pages on push to main
