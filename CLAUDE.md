# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Static D&D world wiki site (Russian language) built with Eleventy (11ty) and deployed to GitHub Pages.

## Development

```bash
npm install
npm run serve    # starts dev server with hot reload
npm run build    # builds to _site/
```

## Architecture

Start from `eleventy.config.js`: it defines all collections (one per content section, sorted with `localeCompare(..., "ru")`), passthrough copies, and the `/dnd.images/` pathPrefix (in `.njk` always pass internal URLs through `| url`; content pages use relative links).

- **Source/output:** `src/` → `_site/` (gitignored)
- **Content sections:** one folder per section under `src/` (Characters, Personalities, Races, Classes, Creatures, Maps). Each has a directory data file `src/<Section>/<Section>.json` (layout, tags, etc.) and an index page using the `list.njk` layout with `collectionTag` front matter
- **Standalone pages:** `src/Glossary/`, `src/Rules/` — self-contained front matter, excluded from collections
- **Layouts:** see `src/_includes/` — `base.njk` is the HTML wrapper (top nav, breadcrumbs, auto-TOC built from h2/h3, initiative tracker shell); section layouts (`character.njk`, `personalities.njk`, `creature.njk`, `race.njk`) chain to it
- **Stat components:** character/personality/creature pages keep ability scores and combat values in front matter (`stats:`, `combat:` — see any `src/Characters/*/index.md` for the format), rendered by `src/_includes/stat-block.njk` and `src/_includes/combat-block.njk` (modifiers are computed in the template; combat notes render as popovers)
- **Battle widgets:** `<battle-toolbar>` and `<add-to-battle>` come from the neighboring dice-roller repo, loaded remotely from `https://ramil-k.github.io/dice-roller/` by `src/scripts/battle-config.js` — the only eager script of the widgets: it imports `battle-toolbar.js` (the dock, every page), sets the Russian instance adjectives via `BattleToolbar.adjectives`, and dynamically imports `add-to-battle.js` only when the page has an `<add-to-battle>` and `roll-dice.js` only when it has `<roll-dice>`/`<roll-any-dice>`/`<roll-log>`. The battle screen, dice overlay and the sync chunk (yjs) load only when activated (dock click, «В бой», invite link) — a configured room does not connect on plain page loads. The toolbar is a dock flush in the bottom-right corner (initiative / battle map / dice buttons); the first two open the shared **battle screen** — a full-viewport grid with the map, the token pool row and the embedded initiative tracker stacked on the left and a toolbar column on the right (map tools on top, dock-style area toggles + d20 at the bottom; Escape closes, no close button). The initiative button opens the tracker as a HUD without the map — the page stays visible and clickable through the empty map cell; area toggles persist in localStorage `battle-mat-ui`; the screen survives navigation between site pages within a tab (per-tab flag in sessionStorage `battle-mat-screen`, set on open, cleared by Escape — the toolbar reopens it on the next page in the same shape, other tabs unaffected). Everything shares one encounter document (localStorage `battle-mat-canvas`, cross-tab sync) — combatants, combat stats, grid and viewport all live in that single JSON Canvas doc. Every «В бой» click adds one combatant *instance* to the encounter (later instances of a type get a random Russian adjective from `src/scripts/battle-config.js`, which also imports `add-to-battle.js`); the combatant shows in the tracker at once but starts **unplaced** (`x-battleMat.placed:false`) — it appears in the screen's **Reserve** pool tab and is drawn on the map only when the DM drags/click-places it from Reserve. The sync button in the screen toolbar opens the room panel (`label-sync*` strings): rooms live on the dice-roller-sync server (`https://universal.ramilkarimov.me:9443`, repo `ramil-k/dice-roller-sync`, local checkout `~/Projects/dice-roller-sync` — `src/server.js` REST + ws gate, `src/wsdoc.js` vendored y-websocket server on yjs 13, `src/persistence.js` one `.yupdate` blob per room, `src/images.js` per-room image store; a push to its main deploys to `/opt/dice-roller-sync` on the host via GH Actions) and let several devices co-edit one encounter over Yjs CRDT; the client half is `~/Projects/dice-roller` (`src/battle-mat/sync.js` bridge plain doc ↔ Y.Doc, `store.js`, `tracker.js`, `overlay.js`; a push to its main rebuilds `dist/` into GitHub Pages, which is what `base.njk` loads — nothing to commit under `dist/`). Attached map images are uploaded to the room's image store (`POST /rooms/<code>/images`) and referenced by URL once a session is connected; outside a room they stay inline as data URIs. `<add-to-battle>` resolves the site-relative `image` to an absolute URL so avatars work for peers on another origin; the room name in the panel is an invite link (`<page>#bm-room=<code>` — opening it on any site page joins the room, the hash is stripped after). Room members see each other's cursors on the map and colored focus rings on tracker inputs; the panel has a name field and a color palette (localStorage `battle-mat-profile`), the name falls back to the tg-login profile, and every player's name is prefixed with an adjective from the same Russian list in `battle-config.js` that names duplicate combatants. Attached map images can be resized by handles and locked (`label-image`/`label-lock`/`label-unlock`/`label-imageremove`). Tracker rows have an editable name; UI strings are localized via `label-*` attributes on `<battle-toolbar>` in `base.njk`; dock theming in `shared.css` via `--bt-*` (`--bm-atb-*` for add-to-battle; the battle screen itself uses its own dark `--bm-*` palette). The standalone `<battle-mat>`/`<initiative-tracker>`/`<roll-any-dice>` launchers still exist in the package but the site no longer mounts them
- **Telegram login:** `src/scripts/tg-login.js` — `<tg-login>` web component (identification only, no server, popup answer trusted as is); mounted in the top nav in `base.njk`, hides itself until its `bot-id` attribute is filled in. Profile in localStorage (`dnd-tg-user`); other scripts read it via `currentUser()` or the `tg-auth-change` window event
- **Head crops:** `swift tools/headcrop.swift <portrait> <dir>/head.jpg` — 320×320 square head close-up (Vision: face → body-pose → animal → saliency); every character/personality/creature gets one, the home page and «В бой» use it via the computed `previewImage` (first existing of `preview` / `portrait` / `gallery[0]`)
- **Icons:** `src/icons/` — SVGs from Sergey Chikin's free set (https://sergeychikin.ru/365/, download as `https://sergeychikin.ru/365/<category>/<name>.svg`). Render icons at 40px or larger — never smaller
- **Feats and alchemy:** feats are a shared system, not a rogue-only one — the whole registry lives in `src/_data/feats.js` and renders on the standalone page `src/Feats/` (`src/Feats/index.html`). A feat's `classes` field sets availability: absent means any class may take it, `["rogue"]` means it belongs to that class. **How a character gets a feat:** the rogue picks one per level; every other class takes one **instead of an ability score improvement** — each class table row that offers «Повышение характеристик» also offers «общая черта» linking to `/Feats/`, and each class page carries a «Черты» paragraph after its level table. `{% featList %}` renders every card plus a three-axis filter toolbar (group / sphere of influence / availability, `src/scripts/feat-filter.js`, loaded when a page sets `featFilter: true`); `{% featList "rogue" %}` on a class page ships with that class chip already pressed, so the page opens filtered but the chip can be unpressed to see everything. Cards on class pages carry no `id` — a feat's canonical anchor is `/Feats/#feat-<id>`, and `{% featPicks "id:level:note; ..." %}` on character/personality pages links there. Optional `side: "shadow"|"panache"` (Тень / Кураж) is rogue-only flavour: a third card icon and a colored left border. Shortcode asset and link paths go through the `url` filter, so cards render at any page depth. Alchemy (`/Feats/#alchemy`) is Morrowind-style: `src/_data/alchemy.js` holds tiers, effects (harm/boon, save, three stack rows), ingredients (region + four effect ids, mixed harm and boon, every effect on at least two ingredients) and основы. **The alchemist tier is the number of alchemy feats taken** (one feat = one tier, repeats count) — `tiers` maps that to dose capacity (3/4/5/6/7) and the DC bonus (2/3/4/5/6); poison DC is 8 + tier bonus + Int. An effect lands if at least two ingredients share it, its strength is that count minus one; the same dose is a poison on a blade or a potion when drunk. Shortcodes: `{% effectCards "harm" %}`, `{% ingredientCards "region" %}`, `{% baseCards %}` on the Feats page, `{% ingredientPicks "id:note; ..." %}` on character pages; `{% alchemyLab "known:page; tier:…; int:…; still:…; retort:…" %}` renders a «Сварить дозу» button opening the brewing calculator in a `<dialog>` (`src/scripts/alchemy-lab.js`, loaded when the page sets `alchemyLab: true`; capacity and DC bonus come from `tiers` in the payload, not from the script; `known:page` limits the picker to the ids that `ingredientPicks` on the same page stores in `data-known-ingredients`). Alchemy has **two entry feats**: `apothecary-kit` (herbs, poisons and potions — every «Повсюду» herb plus the home region's, +1 per level, more by exploring regions) and `demolition` (gunpowder — grants the thrown bases regardless of tier and knows only powder/naphtha/brimstone); either one makes a character an Ученик, both together a Подмастерье. `poisoner` strips a boon from a dose, `apothecary` strips a harm and adds a dose, both repeatable and both raising the tier; `assay` identifies substances; `heavy-charge` (repeatable) widens thrown radius; `anatomist` harvests trophies and unlocks the `mutagen` base. **Two ranger subsystems live here now.** Trophies are ingredients in the `trophy` region (harvested from a monster's corpse, keep for a month), and the `mutagen` base makes a dose permanent — boons stay forever, and every harm in the mix stays too as the price, with no save. Brewing and wearing are deliberately different feats: `anatomist` brews (and may hand the mutagen to someone else), while `graft` — the only new feat in the `common` group, and the one feat that does **not** raise the alchemist tier because it teaches no craft — lets a body carry one mutation per taking. `bomb`/`fire`/`smoke` are thrown bases costing 2 slots that hit an area without distinguishing friend from foe; effects `blast`/`burn` use a Ловкость save. `{% mutagenCards %}` renders the trophy list on the ranger page. The ranger's Охотник на чудовищ gets free `graft` at 3 and four more at 15; Арсеналист gets free `demolition` + `heavy-charge` at 11. The rogue class (`src/Classes/rogue/`) has no subclasses — it picks one feat per level and its class resource is the two-sided scale «Тень ↔ Кураж» (`#scale` section)
- **Dice widgets:** `<roll-dice>`/`<roll-any-dice>` custom elements from dice-roller; `battle-config.js` loads `roll-dice.js` only on pages that contain them
- **Styling:** `src/styles/shared.css` — single stylesheet; theme colors/fonts/shadows are CSS variables in `:root`, use them instead of hardcoded values
- **Deployment:** `.github/workflows/deploy.yml` — builds and deploys to GitHub Pages on push to main
